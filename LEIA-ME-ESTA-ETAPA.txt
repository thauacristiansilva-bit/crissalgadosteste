SABORFLOW - LANDING VISUAL E TESTE GRATIS BASICO

COMO APLICAR
1. Extraia este ZIP.
2. Copie app, components, lib, public e scripts para a pasta ORIGINAL do projeto.
3. Aceite substituir os arquivos de mesmo nome. Nao apague as pastas existentes.
4. Abra a pasta original no VS Code e rode:

npm run typecheck
node --test scripts/test-basic-trial.cjs

Se nao aparecer erro, rode:

git add app components lib public scripts
git commit -m "Adiciona landing visual e teste gratis de gestao basica"
git push origin main

5. Aguarde o deploy do Railway. Atualize a pagina inicial com Ctrl+F5.
6. Clique em Testar gratis. O cadastro fica em /teste-gratis.

O QUE FOI FEITO
- Pagina com imagem de atendimento, cardapio ilustrado em celular e fluxo interativo.
- Cabecalho fixo com botao de teste gratis, inclusive no celular.
- Perguntas: nome da loja, ramo, experiencia com sistemas e volume de pedidos.
- Cadastro usando o acesso comercial existente: nome, CPF, email, senha e aceite dos termos.
- Teste de 7 dias, sem cartao, sem cobranca automatica, com 1 loja, 1 acesso e ate 30 produtos.
- Painel basico: produtos, categorias, complementos, pedidos, PDV, cozinha, clientes e caixa.
- Configuracoes simples: dados/endereco, horarios, retirada/entrega e pagamento presencial.
- Comeca sem clientes, produtos ou pedidos ficticios. Recebimento online inicialmente pausado.
- Perfil do negocio salvo nos metadados do teste. Nao ha contato comercial automatico.
- IA desativada nas configuracoes e bloqueada nas APIs do teste basico.
- Impressao externa, dominio proprio, emissao fiscal e integracoes externas nao fazem parte do teste.

PRIMEIRO USO DO CLIENTE
Cadastre o primeiro produto. Abra Nova venda para registrar uma venda no PDV.
Para receber pelo cardapio, confira os dados nas Configuracoes e ative Receber pedidos.
Para voltar outro dia, abra /teste-gratis, clique em Ja iniciei meu teste e entre com a mesma conta.
O sistema retoma o ambiente ativo e conserva o prazo original. Ao final, o acesso e pausado.
A contratacao paga continua pelo fluxo existente. Esta etapa nao implementa migracao automatica dos dados do teste para uma assinatura paga.

BANCO E INSTALACAO
Nao ha novas dependencias ou migrations nesta etapa. Utiliza a estrutura de demos ja existente (migration 016) e as tabelas atuais de catalogo, pedidos, clientes e operacao.
As respostas sao armazenadas em sf_demo_environments.metadata.businessProfile.
Nao e necessario alterar DEMO_TRIAL_DAYS: o novo teste basico usa 7 dias.
As demonstracoes antigas sao preservadas; uma demo completa ativa nao e convertida silenciosamente em teste basico.

VALIDACAO REALIZADA
- npm run typecheck: passou.
- npm run build: passou (apos recriar o cache local do Next).
- 8 testes automatizados com adaptador de banco isolado: passaram.
- Pagina inicial, /teste-gratis e /demo responderam HTTP 200, e a imagem carregou.
- Inicio de teste sem autenticacao retornou HTTP 401.
- Nao foi realizado cadastro no PostgreSQL de producao nem conferencia visual em navegador. O navegador de teste nao estava disponivel neste ambiente.

CONFERENCIA DEPOIS DO DEPLOY
Crie uma conta de teste, responda as perguntas e confira o painel basico. Cadastre um produto, registre uma venda e saia/entre novamente pela pagina do teste. Confira o menu fixo e o fluxo interativo no computador e no celular.
